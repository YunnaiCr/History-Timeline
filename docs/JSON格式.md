# JSON 数据格式

应用的数据导入 / 导出都使用下面这一种格式。它是**给人读、给人写**的：日期用普通日期字符串，类别和标签用名字，不含任何内部编号。

## 完整示例

```json
{
  "version": 1,
  "exportedAt": "2026-11-07T06:12:33.000Z",
  "categories": [
    { "id": "politics", "name": "政治", "color": "#e05c5c" },
    { "id": "war",      "name": "战争", "color": "#8a6d3b" }
  ],
  "tags": [
    { "id": "t-zg", "name": "中国史" }
  ],
  "events": [
    {
      "id": "e7",
      "title": "辛亥革命",
      "start": "1911-10-10",
      "end": "1912-02-12",
      "dateText": "1911年10月–1912年2月",
      "category": "政治",
      "tags": ["中国史"],
      "summary": "武昌起义，清帝退位，结束两千年帝制。",
      "importance": 1
    },
    {
      "title": "甲午战争",
      "start": "1894-07-25",
      "end": "1895-04-17",
      "category": "战争",
      "tags": ["中国史"],
      "importance": 1,
      "id": "e5"
    },
    {
      "title": "黄海海战",
      "start": "1894-09-17",
      "category": "战争",
      "parent": "甲午战争"
    }
  ]
}
```

## 顶层字段

| 字段 | 必填 | 说明 |
|---|---|---|
| `version` | 否 | 固定为 `1`。省略也按 1 处理 |
| `events` | **是** | 事件数组 |
| `categories` | 否 | 类别定义。只用来还原颜色；省略时用应用内已有的类别 |
| `tags` | 否 | 标签定义。只用来保持 id 稳定；省略时按名字自动匹配或新建 |
| `exportedAt` | 否 | 导出时间，仅作记录，导入时忽略 |

## 事件字段

| 字段 | 必填 | 类型 | 说明 |
|---|---|---|---|
| `title` | **是** | 字符串 | 事件标题 |
| `start` | **是** | 字符串 | 开始时间，见下方「日期写法」 |
| `end` | 否 | 字符串 | 结束时间。**省略表示一个时间点**，填写表示持续一段时间的事件 |
| `category` | 否 | 字符串 | 类别**名称**。不存在会自动创建；省略时归到第一个类别 |
| `tags` | 否 | 字符串数组 | 标签**名称**列表。不存在会自动创建 |
| `summary` | 否 | 字符串 | 一句话摘要 |
| `importance` | 否 | `1` / `2` / `3` | 重要度：1 高、2 中、3 低（默认 2）。时间轴缩得很小时只保留 1 |
| `dateText` | 否 | 字符串 | 显示用的原始日期文本。用于「约公元前 1046 年」这类无法精确表示的表述；省略时由 `start` 自动生成 |
| `parent` | 否 | 字符串 | 父事件的 `id` 或 `title`。填写后本事件成为子事件，展开父事件时显示在轴线上方 |
| `id` | 否 | 字符串 | 事件标识。**手写时可以完全省略**，导入时自动生成；导出时会带上，用于稳定引用 |

### 关于 `parent`

`parent` 可以写父事件的 `id`，也可以直接写父事件的**标题**（更利于手写）：

```json
{ "title": "黄海海战", "start": "1894-09-17", "parent": "甲午战争" }
```

父事件必须是**区间事件**（有 `end`），且子事件的时间应落在父事件区间内，否则时间轴的展开布局会不自然。

## 日期写法

`start` 和 `end` 都支持下面这些写法：

| 写法 | 含义 |
|---|---|
| `"1911"` | 1911 年 1 月 1 日 |
| `"1911-10"` | 1911 年 10 月 1 日 |
| `"1911-10-10"` | 1911 年 10 月 10 日 |
| `"1911年10月10日"` | 同上 |
| `"-221"` | **公元前** 221 年 1 月 1 日 |
| `"-221-01-01"` | 公元前 221 年 1 月 1 日 |
| `"公元前221年"` | 同上 |

> **负数表示公元前。** `-221` 是公元前 221 年，不是"公元 -221 年"。

## 最小可用文件

只写标题和时间也能导入：

```json
{
  "events": [
    { "title": "我记的第一件事", "start": "1911-10-10" },
    { "title": "商鞅变法", "start": "-356", "end": "-338" }
  ]
}
```

导入时：

- 自动生成 `id`
- 归到第一个类别
- 不带标签
- 重要度设为 2

## 导入的两种模式

| 模式 | 行为 |
|---|---|
| **合并** | 把文件里的事件**追加**到现有数据；已有事件一条不动。类别、标签按名称对齐（同名复用，不同名追加）。事件的 `id` 与现有冲突时自动分配新 id |
| **覆盖** | 清空当前数据，只保留文件内容 |

合并模式下，可以先导出一个文件、手工加几条、再导入回来，不会产生重复。

## 与内部格式的关系

应用内部存的是「儒略日整数 + 类别 id + 标签 id」，因为这样排序、比较、跨世纪计算都不会出错。导出时会转换成上面这种可读形式。

导入同时接受两种形式，所以旧版本导出的文件仍然可以导入：

```json
{
  "title": "辛亥革命",
  "startJdn": 2419403,
  "categoryId": "politics",
  "tagIds": ["t-zg"]
}
```

新写数据请用可读格式。

## 常见错误

导入失败时应用会指出是第几条、错在哪里。几个典型情况：

| 报错 | 原因 |
|---|---|
| `第 3 条事件的 start 无法解析：「1911年10月」` | 日期写法不在支持列表里 |
| `第 5 条事件缺少 title` | 标题为空 |
| `第 2 条事件的结束时间早于开始时间` | `end` 早于 `start` |
| `不是合法的 JSON 文件` | 少了逗号、引号没配对等 |
| `缺少 events 数组` | 顶层没有 `events` |

JSON 不允许注释和末尾多余的逗号，这是最常见的两个手写错误。
